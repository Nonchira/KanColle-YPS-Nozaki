# オリジナル更新時の移植ガイド

このフォルダはNozakiTimer v1.0.1の接続箇所・基準ファイル・差分をまとめたものです。**稼働版へ自動上書きするツールではありません。** 新しいオリジナルを別フォルダへ展開し、必要な機能だけを確認して移植します。

## 内容

| 資料 | 用途 |
|---|---|
| FEATURES.md | 機能別のファイル・関数・API接続点・依存関係 |
| CODEX-HANDOFF.md | 次回作業者が守る制約、作業順序、完了条件 |
| baseline/ と baseline.json | 実際に元にした主要接続ファイルとSHA-256 |
| patches/ | 基準版から公開版への共有ファイルの差分（新上流へ無条件適用不可） |
| release-files.json | 公開版の全配布ファイルとSHA-256（このファイル自体を除く） |
| inspect-upstream.py | 上流候補と基準・現行版を比較する読取専用ツール |

追加モジュールの正本はルートのnozaki*.js、senka*.js、compass/です。Update内に重複した実行版を作りません。baselineは接続ファイルだけの抜粋であり、単独実行やゲーム導入用ではありません。

## 作業手順

1. 稼働版とブラウザ記録を退避し、新上流・作業候補・稼働版を分離します。.gitとブラウザDBは配布物に含めません。
2. 配布ルートで比較します。コマンド末尾には、別途展開した上流フォルダを指定します。

   ```text
   python Update/inspect-upstream.py ../upstream-candidate
   ```

3. 上流に追加済みの機能を調べ、二重に追加しません。両方が変更したファイルはpatchの一致だけで採用せず、関数・受信API・表示・保存構造を比較します。
4. FEATURES.mdに沿い、追加モジュールと必要な接続だけを作業候補へ移植します。現在の実装は共有ファイルを変更するため、完全な独立プラグインではありません。
5. 権限・通信先・データ保存形式の変更をレビューし、docs/TESTING.mdの検証と実ゲーム確認を行います。
6. 問題がなければ同じ拡張機能の展開先へ反映し、F12・ゲームページ・コンパスを開き直します。
7. 移植後の基準、差分、ハッシュ、マイナーバージョンの履歴を更新します。競合や不明点を残したまま成功扱いにしません。

## 以前の更新ツールについて

従来の自動更新ツールは旧構成のテスト・既定フォルダ配置に依存し、現在の遅延ローダーやコンパスの全テストを検証しません。実行履歴も個別環境に紐づきます。そのままの流用は採用せず、公開版ではこの読取専用比較と移植手順に置き換えました。旧ツールのbaselineや復元履歴は、個別のバックアップとして保持してください。

## 復元

更新候補を検証するまでは稼働版を変更しません。反映後に問題が出たら、ゲームとF12を閉じ、退避した同じ版のファイル一式へ戻します。ブラウザDBを自動消去しません。将来DB構造を変える場合は別途移行・復元計画が必要です。

## 差分の検査

同梱patchは旧基準の作業コピーに対して `git apply --ignore-whitespace --check` で検査し、適用後のテキストが公開版と一致することを確認しています（改行形式の差は除外）。新上流へ無条件に適用する手順ではありません。元のbaselineはバイト単位のハッシュを保持しています。
