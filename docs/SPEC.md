# KanColle-YPS v2.3.1 +NozakiTimer v1.0.0仕様書

この文書を本派生版の仕様として扱います。上流KanColle-YPSを基に、野埼タイマーを中心に、戦果メモ、行動履歴、艦隊コンパス、任務・期限管理を追加した非公式派生版です。

## 目的

艦これの通常プレイ中にDevToolsが受信した情報を整理し、母港画面の状況、野埼の給糧効果、戦果任務、通常海域・遠征の履歴を確認しやすくします。ゲームへの追加操作や自動プレイは行いません。

## 対象範囲

### 野埼タイマー

野埼・野埼改が旗艦または2番艦にいる艦隊を対象に、編成変更成功時からの経過時間と、母港へ戻った場合の推定condを表示します。要約値は対象随伴艦の最低推定condです。上限は54で、推定値が54に到達した場合は要約行を赤色にします。

ゲームサーバーから開始時刻や給糧確定値を取得するものではありません。30秒の安全余裕を置き、監視していない時間の操作・給糧回数・自然回復を推測しません。実値を受信した場合は実値を基準に再計算します。

### 戦果メモ

EO、クォータリー・イヤーリー戦果任務、海域別の必要回数、7-2のゲージを表示します。受信できなかった過去分は手動補正できますが、ゲームへ送信しません。任務の出典は艦これWiki、個別条件の参考資料は各READMEに記載します。

### 行動履歴

受信した通常海域の出撃結果と遠征結果を、日時、通番、海域・遠征名、勝利ランク等で一覧表示します。未受信の行動やスマホ利用中の行動は補完しません。

### 艦隊コンパス

通常海域のゲージ別編成候補、遠征条件、戦果、ドロップ、任務・期限を別画面で表示します。海域編成の参考元はぜかましねっと等、任務・遠征の定義は艦これWiki等です。外部サイトを実行時に取得しません。

## 通信・保存の境界

- 新機能はDevToolsで受信したレスポンス本文を利用します。
- 新しいゲームAPIリクエスト、再送、自動操作は行いません。
- 既存YPSの処理と競合しないよう、追加の受信処理は成功応答後に実行します。
- 個人データは使用中のブラウザ内に保存します。別PC・スマホとの同期は行いません。
- 推定、受信事実、手動補正、未確認を別状態として表示します。

## 仕様上の優先順位

1. ゲームから受信した実値
2. YPSが保持している受信済み状態
3. 本派生版の計算による推定値
4. ユーザーが入力した手動補正

推定値や手動補正は、実値を上書きしません。矛盾がある場合は再確認待ちとして表示します。

## 採用・分割方針

上流へ提案する場合は、次の単位に分けます。

1. 野埼タイマー計算モデルとテスト
2. DevTools受信処理への接続
3. 野埼タイマーUI
4. 行動履歴・戦果メモ
5. 艦隊コンパス・任務管理

野埼タイマーの採用を、艦隊コンパス全体の採用条件にしません。各機能の出典、制限、テストを添えて、上流の構造に合わせて取り込めるようにします。

## フォーク運用方針

- 本派生版をフォーク先の基準版とします。
- 上流の更新は自動統合せず、ユーザーが指定した時点で確認します。
- 上流更新と本派生版の変更が同じファイルにある場合は、機能ごとに手動で移植します。
- 元版の著作権表示、原作者表記、第三者データの出典・条件を保持します。
- 公開時は出典と再利用条件を確認し、公開先やIssue/PRの扱いを別途決定します。

## v1.0.0の起動・表示

コンパスの受信本文は軽量ローダーで一時保持し、YPSの成功した母港処理後に保存・集計モジュールを読み込みます。受信順序と日時を維持し、処理失敗をゲームAPIの再送で補いません。初期画面は行動履歴で、通常海域／遠征の別タブと日別・種類別連番を持ちます。各画面は必要な履歴だけ取得し、行動履歴は256件単位で読み出します。
