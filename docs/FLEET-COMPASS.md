# 艦隊コンパス

**KanColle-YPS v2.3.1 +NozakiTimer v1.0.1** から開く、受信データを利用したローカルダッシュボードです。

## 開き方

1. 本改良版を展開し、manifest.jsonがあるフォルダをChromeの「パッケージ化されていない拡張機能を読み込む」で指定します。
2. ゲーム開始前にF12を開き、通常操作で母港を受信します。
3. ゲーム画面上部の「艦隊コンパス」を押すと、別タブで開きます。

更新後は拡張機能を再読み込みし、F12・ゲームページ・艦隊コンパスを開き直してください。「デモを見る」は架空データによる表示で、実データの記録には書き込みません。

## 画面の並びと配色

受信記録と任務の派生集計は別々に処理します。任務集計は関連する受信時にまとめて実行し、連続する画面更新もまとめることで、戦闘中の処理待ちを抑えます。受信順序は維持し、ゲームへの追加通信は行いません。

上部タブは「行動履歴」「ドロップ履歴」「通常海域 編成・装備ジェネレーター」「遠征 編成・装備ジェネレーター」「戦果」「任務・期限管理」の順です。最初に開く画面は行動履歴です。

薄いグレーを基調に、見出し帯・選択項目・表の交互色で区切ったライト配色です。狭い画面では上部タブを横にスクロールできます。

## 通常海域 編成・装備ジェネレーター

登録済みの海域・ゲージ別の参考編成を、受信した保有艦・装備へ置き換えて候補を提案します。5-6・7-2・7-3・7-5は段階別に選択できます。自動比較では異なる艦種構成を優先し、「編成パターン」から個別の軽量・重量等も選べます。

- 自動: 手持ちから艦娘と装備を選び、最大3候補を比較。
- 手動: 選択した艦娘と順序を保持し、装備案を提示。
- 補完: 選択した艦を固定し、残りの艦娘と装備を提案。
- 方針: 通常・対空優先・対潜優先・通常＋対空＋対潜。

装備は保有ID単位で重複を防ぎ、受信マスターに基づいて配分します。大破・入渠・遠征・耐久不明の艦は除外し、固定艦が該当する場合は理由を表示します。増設は現装備を保持します。

未登録・期限切れの海域について、汎用編成を攻略候補として自動生成しません。手動固定編成が登録条件に合わない場合は、その旨を表示して装備案と区別します。

参考編成の出典は[ぜかましねっと艦これ！](https://zekamashi.net/)を中心とし、各テンプレートに参照先を保持しています。候補は独自評価による比較案です。ルート到達、制空値、索敵、先制対潜、対空CI、特効・札・個別装備制限・勝率の成立を保証しません。

## 遠征 編成・装備ジェネレーター

成功条件と大成功条件を上部で確認し、選択艦隊の旗艦Lv・合計Lv・艦種・ドラム缶数／搭載隻数・キラと照合します。必要ステータスは表示しますが、遠征用の装備補正計算や未確認の代替編成は未判定です。下段の重複説明は削除し、装備欄には照合対象の現在装備を表示します。

海域名・艦種略記・条件の参考元は[艦これWiki「遠征」](https://wikiwiki.jp/kancolle/%E9%81%A0%E5%BE%81)です。実行時に攻略サイトを自動取得する機能はありません。

## 戦果・ドロップ

母港・基本情報で観測した提督経験値の増分から、通常戦果を「増分 × 7 / 10000」で計算します。月選択、累積グラフ、計算機を利用でき、EO・任務・引継ぎは対象月と根拠メモを手入力できます。計算の出典は[艦これWiki「称号・戦果」](https://wikiwiki.jp/kancolle/称号・戦果)です。

初回観測以前の通常戦果は不明です。月区分は月末22時JSTを境界とし、境界をまたぐ経験値差を推測配分しません。表示合計は公式ランキング値ではありません。

ドロップは保存済みの戦闘結果から、日時（JST）・艦名・海域・マス記号・勝敗を1行ずつ表示します。50件／100件を選び、新しい順にページ送りできます。直近150受信より古い保存記録も対象ですが、未受信・未保存のドロップは復元できません。

## 行動履歴

通常海域と遠征は行動履歴内の2つのタブで切り替えます。番号は日別・種類別に1から付け、日付の絞り込みと50件ずつのページ切替でも維持します。過去の保存記録にも適用します。

初回は「保存データを読み込み中…」と表示し、読み込み完了後に履歴の有無を表示します。再更新中は既存の一覧を残して右上に「読み込み中…」と表示します。

履歴は表示中のタブに必要なものだけを読み込みます。行動履歴を開くときに戦果・任務の全履歴を読み終えるのを待たず、各タブへ切り替えた時点で取得します。

通常海域は1出撃を1行にまとめ、最後に受信した戦闘ランクとマスを表示します。道中撤退をボスクリアとは判定しません。7-2はボスマスで第1・第2ゲージを識別します。

進撃記録なしに次の戦闘結果が続いた場合、前のマスを流用せず「マス 不明 / 進撃記録欠落」と表示します。記録詳細で受信した移動・戦闘結果を確認できます。保存済み記録そのものは書き換えません。

受信本文は通常形式とBase64形式に対応し、読取失敗時はChrome内の同じ受信本文を一度だけ読み直します（ゲームへの再送ではありません）。それでも読めない場合は本文・URLを保存せず、失敗したAPI種別の記録を残します。

最終戦のマスは「J」「M」等のマップ記号で表示します。内部番号を単純なアルファベット順には置き換えず、[KC3Kaiの海域対応表](https://github.com/KC3Kai/KC3Kai/blob/6b0534d291c27220da1b6fe454e91fc96a6a7b27/src/data/edges.json)の到達先を使用します。保存済み履歴にも適用され、未登録のマスは「不明」です。対応表は同梱データのみを使い、実行時の外部取得はありません。出典のMITライセンスは LICENSE-KC3Kai.txt に同梱しています。

保存済み全期間の必要な記録を読み、直近150件の表示制限とは分けています。開始未受信・帰港未確認・結果未受信を区別します。受信停止中の周回、未保存の遠征、結果応答がない支援遠征は復元できません。

## 任務・期限管理

周期・状態・任務名で絞り込み、任務名の三角を開くと前提・根拠・受信履歴・今期の補正を確認できます。

| 周期 | 更新時刻（日本時間） |
|---|---|
| 日次 | 毎日5時 |
| 週次 | 月曜5時 |
| 月次 | 毎月1日5時 |
| 四半期 | 3・6・9・12月1日5時 |
| 年次 | 任務固有の更新月1日5時 |
| マンスリー遠征 | 毎月15日12時 |

状態は未確認・未受注・受注中・達成（報酬待ち）・完了・未出現を区別します。起動後は過去の受注を再確認待ちとし、任務一覧を通常操作で開いて受信分を照合します。非表示だけでは完了と判断しません。

任務の分類・前提情報は[艦これWiki「任務」](https://wikiwiki.jp/kancolle/%E4%BB%BB%E5%8B%99)を出典とする台帳を同梱しています。確認できた単純な前提関係だけを判定に使い、未確定・複雑な条件は自動判定しません。周期の異なる前提への誤った流用や、新しい直接受信との矛盾を避けます。

YPSの保存済み報酬受取記録、日週の数値カウンター、戦果メモを連携します。回数は「PC記録」と区別し、スマホ中の未観測分を補完しません。全任務の細目別カウンターは網羅せず、受信した50%・80%フラグ等を使います。

状態補正は今期限定で履歴を残し、解除できます。「海域回数を補正」は右側の戦果メモと同じ記録を使い、F12と母港受信が必要です。

「任務記録を保存／復元」は、任務受信・状態補正・表示用回数の履歴をJSONで保存・追加復元します。既存記録は上書きせず、重複は除きます。**戦果トラッカー本体や全行動履歴の移行機能ではありません。**

## 艦隊データ出力

デッキビルダーv4形式のJSONを確認・コピー・保存できます。未取得装備は警告して省略します。基地航空隊・艦娘の運・現在搭載数等は出力対象外です。デモのIDは架空のため実編成として利用できません。

## 保存と通信の範囲

新しい記録はブラウザ内のIndexedDBへ保存します。一つのChromeプロファイルで一提督を対象とし、複数提督の自動分離・他PCとの同期は行いません。

通常プレイで受信した応答を正規化し、POST内容・Cookie・トークン・提督名・提督ID・元URLは新DBに保存しません。ゲームやDMMへの追加通信、再送、自動操作は行いません。既存YPSの同期機能は別系統です。

母港外の変更は次の関連データ受信まで反映されない場合があります。不明値を推測で埋めず、受信日時と推定の根拠を区別します。

## 開発者向け構成・検証

| ファイル | 役割 |
|---|---|
| core.js | 応答の正規化・状態更新・出力 |
| db.js | IndexedDBの保存と履歴読取 |
| collector-integrated.js | YPSのDevTools受信との連携 |
| dashboard.* | 画面とメニュー |
| generator*.js / expedition-ui.js | 海域の候補生成・遠征の照合 |
| activity.js | 出撃・遠征の履歴表示 |
| quest-manager.js / quest-ui.js | 任務の期間・状態・表示 |
| quest-catalog.js | 出典付き任務台帳 |
| yps-quest-progress.js | 既存YPSの数値カウンター読取 |

ルートから `node --test compass/tests/*.test.js` を実行します。合成データのテストを配布版に同梱しています。利用のためにビルドや開発用コマンドを実行する必要はありません。

艦型表示名は[KC3改の対応表](https://github.com/KC3Kai/kc3-translations/blob/master/data/en/ctype.json)を参照しています。MIT表記は `LICENSE-KC3-translations.txt` に同梱しています。出典URL・取得日時・hashはデータ側に保持し、実行時に外部取得しません。

受信マスター構造の参考元は[kcwikiのAPI定義](https://raw.githubusercontent.com/kcwiki/kancolle-data/master/api/api_start2.ts)です。候補生成・照合は保存済みの艦隊編成を書き換えません。

遠征の行動履歴はID列に受信マスターの表示番号を表示します。名称が一意に一致しない場合やマスター未取得時は「—」です。過去の履歴は書き換えず表示時に照合します。

通常海域の行動履歴は「海域」列で通常海域／追加海域（EO）を区別し、「海域名」に番号と受信マスターの名称を表示します。名称未取得時は番号のみを表示します。表記例は[艦これWikiの鎮守府海域](https://wikiwiki.jp/kancolle/%E9%8E%AE%E5%AE%88%E5%BA%9C%E6%B5%B7%E5%9F%9F)を参照。

詳しい登録範囲・出典・未判定条件は[通常海域・遠征の条件確認](MAP-EXPEDITION-AUDIT.md)を参照してください。
